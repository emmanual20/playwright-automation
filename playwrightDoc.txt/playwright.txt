TYPES OF WAIT=>

- A wait statement is a mechanism that pauses the execution of a test script untill a specific condition is met or a defined timeout period passes.
-These are important for handling dynamic and asynchronous content that doesn't load all at once on modern websites.

WHY ARE WAIT STATEMENTS ARE NECCESSARY?

Without wait statements, your test script might
->Try to click a button before it becomes clickable
->Attempt to read test from an element that hasn't loaded yet
->Fail due to transutions, animations, or slow network resposes.

Wait statements help to:

->reduce flakiness in tests
->Ensures consistency across diffrent environment
->Improve reliabilty and reflect actual user behaviour.

2.Hard-Coded Waits (Static Wait)

    A hardcoded wait is a pause in test execution for a fixed period of time, regardless of whether the application is ready or not
    Syntax-> await page.waitForTimeout(milliseconds)

3. Explicit Wait

    Explicit waits are delibrate conditions that your automation script waits for before processing to the next step. Instead of blindly waiting for a foxed amount of time, they untill a specific condition is met-which makes your tests more reliable and faster.
    Web Applications often load data asynchronously(AJAX,JavaScript rendering).If you try to click, type, or validate something before it's ready, the test will fail.

    Explicit wait so;ves thuis by:

    -Ensuring elements are present ,visible, or in a correct state
    -Waiting for page navigattion or network to completed
    -Verifying text or data appears dynamically

    3.1 Element Based Waits
        ->Wait for text
            Wait untill specific visible text appears on the page (inside any element)
            Syntax: await page.locator('text="Expected text"').waitFor();
        Note:
            -This wait untill an elememt containing the exact text appears and become visible.
            -Case-sensitive by default.

        ->wait for timeout
            Wait for specific timeout with element state (like visible, attached,etc).
            Syntax: await page.locator('#element-id').waitFor({timeout:5000,state:'visible'});

            Parameters:
            -timeout: time in milliseconds
            -state: one of 'attached','detached','visible','hidden'

        ->wait for selector
            Wait untill an element matching the selector appears in the DOM
            Syntax: await page.waitForSelector("#element-id")
        Note:
            You can also add {state: 'visible'} or other states to this function

        ->wait for element state
            Wait for an element to reach a certain DOM state like:
            -visible: shown on screen
            -hidden: in DOM but not shown
            -attached: present in DOM
            -detached: removed from DOM
            Syntax: await page.locator('#element-id').waitFor({state:'Visible'})

    3.2 Page Waits
        ->Navigation wait
            waitForNavigation()
            ->waitForNavigation() is an explicit wait method in Playwright that waits for the page to finish navigating before proceeding.
            This is esential when your test script depends on anew page or URL being loaded, such as after clicking a link or submitting a form.

        ->Load-state wait
         waitForLoadState()
            ->waitForLoadState() is a page-level explicit wait in Playwright that pauses the script untill the page reaches a specific load state.
            It's helpful when you want to make sure the page is ready before interacting with elements,especiall after:
            Navigations,form submissions
            JavaScript based updates
            State (optional) 
            -load: Waits untill the entire pageis loaded (HTML, images,styles,scripts)
            -domcontentloaded: Waits untill the initial HTML is fully parsed
            -networkidle: Waits untill there are no active network connects for at least 500ms

            Syntax: await page.waitForLoadState('state',{options});

        ->waitForEvent()
            ->waitForEvent() is used to pause your script untill a specific event happens on the page or browser context.
            It's usefull when something happens asynchronously or outside your dicrect control- like a new page opening, a file downloading, or a dialog box appearing.

            Syntax: const evenPayLoad = await page.waitForEvent('eventName',{options});

            => eventName: The name of the event to wait for (like 'popup','download','dialogue',etc.)
            options: Optional timeout

    3.3 Custom Wait

        -> waitForFunction()
            waitForFunction() is used to pause your script untill a custom JavaScript consition inside the browser returns true.
            It is helpful when waiting for something that doesn't have a fixed selector or involves dynamic DOM changes, like:

            -A looader disappearing
            -Text appearing
            -Element count increasing

        Syntax: await page.waitForFunction(()=>{ return condition;},options);

        await page.waitForFunction(()=>{document.querySelector('CSS').textContent==='loaded'})

WHAT ARE FRAMES?

A frames (specially, an <iframe>)is an HTML element that embeds another HTML document inside the current page. It acts like a "page within page".
Example:
<iframe src="https://example.com/frame.html" name="login-frame"></iframe>

Frames are used when:
-A third-party service is embedded on a websites
-Content needs to be loaded independently

// Locate element inside frame
const username = await page.frameLocator('.frame-class').getByLabel('User Name');
await username.fill('John');

Frame objects
One can access frame objects using the page.frame() API:

// Get frame using the frame's name attribute
const frame = page.frame('frame-login');

// Get frame using frame's URL
const frame = page.frame({ url: /.*domain.*/ });

// Interact with the frame
await frame.fill('#username-input', 'John');
